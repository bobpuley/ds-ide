SD Card Content Viewer — evaluation notes

Variant A — inline accordion

  • Matches the Peripherals section pattern exactly — zero new layout concept for the user.
  • Preview appears right where you clicked, no eye movement.

Variant A — trade-off

  • A long preview pushes every row below it down — awkward with many files.

Variant B — flyout drawer

  • List stays a fixed height; switching files doesn't reflow anything.
  • More horizontal room for the preview text itself.

Variant B — trade-off

  • Two-pane layout is a new shape not used elsewhere in the Controls Editor yet.
  • 160px list column truncates longer filenames more aggressively.

Open questions

  • Both variants shown with root-level files only, per FR-SD-1 scope — confirm that's still right before committing.
  • Empty state text ("SD card is empty" today) — good enough, or should it hint at how files get created (e.g. the effect calling f_open)?

MIDI Monitor — evaluation notes

Variant A — stacked

  • Single column fits the existing sidebar-webview footprint (MIDI panel is currently narrow).
  • Keyboard, sender, and monitor read top-to-bottom in the order a user acts.

Variant A — trade-off

  • Monitor gets squeezed to ~220px tall — long sessions scroll a lot.

Variant B — two-column

  • Monitor is the tallest element on screen — matches "this is mainly an observability tool" framing.
  • Inputs stay visible while scrolling monitor history.

Variant B — trade-off

  • Needs more total width than today's MIDI panel — check it still fits a docked sidebar, or if this variant implies the panel should default to a wider editor-column placement.

Open questions

  • PC dropdown shows a plain 0–127 list here — real instrument/GM patch names would need a lookup table we don't have; confirm plain numbers are fine for v15.
  • Tx rows here are simulated (no real emulator) — direction color-coding (teal Rx / blue Tx) is the thing to evaluate, not the exact sample data.
