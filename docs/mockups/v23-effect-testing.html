WHAT TO LOOK AT

  1. Input select is the only structural change to the existing bar; the parameter row after it is per-generator.
  2. A/B + Bypass sits on the right of the same row — one click, no rebuild. "A·current / B·prev build" assumes the emulator can keep the last two loaded builds.
  3. Pots strip shows mapped values (1.2 kHz, 35 %) — this relies on P0-5 (range/unit) landing first.
  4. Drawer holds the three "workbench" features so the scope + spectrum stay the hero. Collapsed by default? (open question)
  5. Test tree as a native Test Explorer (vscode.tests): free Run/Debug, gutter icons, CI-friendly output. The webview-free option.

OPEN QUESTIONS

  1. Golden = WAV on disk (big, exact) or hash + tolerance (small, opaque)? Mockup assumes WAV + residual dBFS.
  2. Where do cases live: tests/effect/*.json in the user's project (committed), or in .ds-ide/?
  3. Are automation lanes part of a test case, or reusable on their own? Mockup: both (test stores a lane reference).
  4. A/B: "B" is the previous successful build. Should the user also be able to pin B explicitly?
