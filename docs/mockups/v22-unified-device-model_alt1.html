⚠ MOCKUP — proposal, not decided — M66 palette restyle: v22-palette_alt2.html icon tiles on the unified device model

Same unified model as v22-unified-device-model.html, but on the IDE's real Wiring Editor schematic and with a true drag & drop gesture. Grab a device from the palette: the schematic answers immediately — valid pins (or bus lanes / the USB port) pulse in the device's colour, occupied-but-valid targets show an amber hatch, everything else fades. Hover a target to preview the exact footprint the drop would claim; release to open the unified popover. Release anywhere else to cancel. Click a placed device's pin to open its popover (Show panel for devices with a live view · Reveal in code · Remove). No separate Peripherals list.

Esc cancels a drag in progress.

Evaluation notes

Evaluate: palette style (alt2 icon tiles)

  • Tiles use the illustrated icons from v22-palette_alt2.html, two per row, uppercase label, requirement underneath, lift on hover.
  • The registry accent colour is kept as a short underline and as the hover border, so the colour still matches what the board pulses while you drag.
  • Collapse (◀): the rail shows small icons, not colour dots. Hover one for the name and requirement.
  • Placed peripherals (SD Card, OLED) are faded with a ✓; hover says "placed — drag to move".
  • The drag label shows the icon too.
  • Trade-off: taller tiles, so the palette scrolls sooner in a short sidebar. Collapsing is the escape hatch.

Try these

  • Pot — only the ADC pins (A0–A11, right header) light up.
  • Button / LED / Toggle — every free GPIO lights up; pins inside an enabled bus lane are not offered.
  • RGB LED / Encoder — hover a pin: the 3 pins it would claim are labelled R·G·B / A·B·SW (dropped pin + next free pins in ascending order, as multi-pin-alloc.ts does today). Pins with no room for 2 more free pins after them don't light up.
  • OLED (pre-placed on I2C1) — drag it from the palette: two dashed lanes (SPI1 D7–D10, I2C1 D11–D12); the lane you drop on is the bus choice, so the popover needs no bus dropdown.
  • Click an OLED pin (D11/D12) or its bracket → popover with Show panel. Every device with a live view (OLED, MIDI TRS, MIDI USB) gets it; SD Card and controls don't.
  • MIDI USB — the micro-USB port on top (INTERNAL) and the D29–D30 lane (USB_HS_D). Placed on INTERNAL, click the USB port to reach its popover.
  • MIDI TRS onto its lane while tapLed sits on D14 → amber conflict.
  • There's no Peripherals footer: the palette wires things, and the pin popover handles the rest.

Open: bus-lane pins as plain GPIO

  • Here a lane pin is valid for a single-pin device only while no bus peripheral owns that lane (matches today's editor, where D7–D14 are assignable GPIO). Should they instead be flagged "reserved for SPI1/I2C1" (lit, with a soft warning)?

Open: conflict resolution

  • Same proposal as the base mockup: Relocate existing primary, Replace / Cancel secondary. Relocate is disabled when no free valid target remains for the bumped device.

Open: accessibility / fallback

  • Drag-only has no keyboard path. Candidates: keep click-a-pin popup as a fallback, or "Enter on a palette chip → arrow keys cycle valid targets → Enter drops".

vs the base mockup

  • Real pin geography: users see where on the Seed the device lands, not a regrouped list.
  • Bus devices get a lane-shaped target instead of per-pin glow — one drop = the whole bus.
  • No mode toggle: one gesture only.
