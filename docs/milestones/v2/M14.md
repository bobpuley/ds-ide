# M14 — Session recording

**Status:** released
**Target version:** 0.2.7
**Goal:** Record a run and replay it for regression comparison.

**DoD → AC-16 green** (record a session, then replay it through the pipeline); no regression to
AC-1…AC-14. Sprint-close → CHANGELOG + 0.2.7 tag.

---

## Tasks

- [x] T14.1 — **Format design**: binary `.dsrec` format — 16-byte header + typed records
  (AUDIO_BLOCK, POT_EVENT, BUTTON_EVENT, END). No output stored; re-generated on replay.
- [x] T14.2 — **Record mode** (C4): `SessionRecorder` — `start()`, `enqueuePot/Button()`,
  `writeBlock()`, `stop()`. IPC: `recordStart`/`recordStop`. Pot/button events queued from
  IPC thread, flushed before each block by audio engine.
- [x] T14.3 — **Replay mode** (C4): `SessionPlayer` — `open()`, `nextBlock()`, `close()`.
  Wired into `run_simulated` as input source; fires pot/button events per block. IPC:
  `replayStart`/`replayStop`/`replayDone`. Verified by `tests/runtime/test_recording.py`
  (AC-16: 0.00% output difference live vs replay).
- [x] T14.4 — **UI** (C2): recording bar below audio-source bar — Record / Stop / Replay
  file… buttons; `recordingState` + `replayDone` messages update button states and indicator.
