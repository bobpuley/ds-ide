# M9 — WAV file input

**Status:** released (0.2.1)
**Target version:** 0.2.1
**Goal:** Load a WAV file as a repeating or one-shot audio source for automated regression.

**DoD → AC-10 green** (WAV file plays through the effect as an audio source); no regression to
AC-1…AC-9. Sprint-close → CHANGELOG + 0.2.1 tag.

---

## Tasks

- [x] T9.1 — **WAV reader** (C4): self-contained WAV reader in C4 (`wav_reader.h/.cpp`) — RIFF/WAVE
  parser decoding 8/16/24/32-bit PCM + 32-bit IEEE float, mono/multi-channel, normalized to float.
  No new dependency (per 04 §2.3 / CR-7). Unit test: `tests/wav-reader/run_wav_reader_tests.sh`.
- [x] T9.2 — **Block feed** (C4): `wav_fill_stereo_block()` feeds WAV samples into the simulated
  loop's input buffer (linear resample to engine rate, mono→stereo, loop/one-shot). Unit-tested in
  `tests/wav-reader/`; integration via `tests/runtime/test_wav.py` (AC-10).
- [x] T9.3 — **IPC**: `wavFile {path, loop}` — runtime dispatch loads/activates (empty path
  deactivates, emits `wav_error` event on failure); `EmulatorManager.sendWavFile()` on the TS side.
- [x] T9.4 — **UI** (C2): WAV radio enabled; `Choose WAV…` button (native open dialog via the
  extension), chosen-file label, and a loop toggle. Selection persists across re-deploys; a load
  failure surfaces the `wav_error` event in the scope panel.
