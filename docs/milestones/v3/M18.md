# M18 — Wiring Editor (v0.3.3)

**Status:** released  
**Version:** 0.3.3  
**Depends on:** M17 (C9 convention parser must exist; `controlsConfig` message contract must be stable)  
**Goal:** Ship a new VS Code panel — the Wiring Editor — that shows a Daisy Seed pinout SVG, lets the developer click a pin to assign a physical device, and writes a C++ declaration to the ds-ide:controls block in the project's effect source.

---

## Context

The Wiring Editor (C10) is a design-time tool for mapping physical hardware devices (pots, buttons, LEDs) to Daisy Seed pins. It is separate from the Controls Editor (C2) and does not interact with the running emulator. It writes C++ declarations that the Controls Editor (C9) later reads.

Data flow: Wiring Editor (C10) writes C++ → C9 parses → Controls Editor (C2) renders.

### T18-2 ✅ — Create Daisy Seed pinout SVG asset

Author a schematic-style SVG showing the Daisy Seed pin header (all 40 pins labeled:
D0–D30, A0–A11, 3V3, GND, AGND, AVDD, VIN, BOOT). Each pin is an SVG element with a
`data-pin` attribute and a clickable hit area. Assigned pins carry a visual indicator;
unassigned pins appear neutral.

**DoD:**
- SVG renders clearly in a VS Code webview.
- All 40 pins are labeled and individually clickable.
- Assigned vs. unassigned state is visually distinct.

### T18-3 ✅ — Implement click-to-assign interaction

In the Wiring Editor webview:
- Clicking an unassigned pin opens a floating popup listing: Pot, Button, LED.
- If the device type may be invalid for the pin (non-ADC pin + Pot), show a warning badge next
  to the option (do not disable it).
- The popup includes an editable `id` field pre-filled with the default `<kind><n>` (e.g.
  `pot1`). On confirm, the webview validates that the id is non-empty and unique within the
  already-known wiredPins; shows an inline error if not.
- On confirm: send `{pinNumber, deviceType, id}` to C1 (via postMessage); `label` = `id`.
- C1 writes the declaration to the C++ convention block (T18-4); returns updated `wiredPins[]`.
- Webview updates the SVG to reflect the new assignment.

**DoD:**
- Clicking unassigned pin shows popup with all three device types.
- Pot on non-ADC pin shows a visible warning.
- id field defaults to `<kind><n>`; duplicate id shows an inline error and blocks confirm.
- After selection: control icon appears on the pin; C++ file is updated.
- Clicking an assigned pin shows its device type and id with a Remove button.
- Confirming Remove: annotation line is gone from C++ source; pin shows as unassigned in SVG.

### T18-4 ✅ — Implement C++ convention block writer (C1)

C1 module (`src/wiring/controls-writer.ts`) that:
- Reads the project's effect source file: checks `ds-ide.effectSource` workspace setting
  first; if unset, auto-detects the first `.cpp` adjacent to `CMakeLists.txt`
- Locates the `// ds-ide:controls:begin` … `// ds-ide:controls:end` block; creates it if absent
  (appended to end of file before final `}`)
- Inserts a new declaration line before `// ds-ide:controls:end`:
  `TypeName varname; // ds-ide: id=<id>, kind=<pot|button|led>, pin=<n>`
  where TypeName is: `AdcChannelConfig` for pot, `Switch` for button, `Led` for led
- Write is performed via VS Code's workspace edit API (undoable with Ctrl+Z)

**DoD:**
- Unit tests: block present + insert; block absent + create; file-not-found error surfaced.
- Undo via Ctrl+Z restores the original file state.
