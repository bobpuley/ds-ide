# M22 — Secondary Sidebar Panels

**Target version:** 0.4.3
**Status:** in progress
**Closes:** AC-34, AC-35
**Decisions:** D21 (Controls Editor and Wiring Editor as secondary sidebar `WebviewView`s)
**Risks:** R23 (C2 split regression), R24 (`WebviewView` lifecycle)

---

## Goal

Move the Controls Editor and Wiring Editor from floating `WebviewPanel`s into persistent
`WebviewView`s in a ds-ide secondary sidebar container (C11). Both views are always accessible
in the right panel without running a command.

---

## Tasks

### T22-1 — Extract Controls Editor from C2 into C11 (`WebviewView`) ✅

**Context:** C2 currently bundles Scope, Controls, and Spectrum in one webview panel. This
task extracts the Controls Editor section into a standalone `WebviewView` provider, leaving
C2 with Scope and Spectrum only.

- [x] Add `contributes.viewsContainers.activitybar` entry for `ds-ide-sidebar` in `package.json`.
- [x] Add two `contributes.views` entries under `ds-ide-sidebar`:
  - `ds-ide.controlsEditor` (name: "Controls")
  - `ds-ide.wiringEditor` (name: "Wiring")
- [x] Implement `ControlsViewProvider implements WebviewViewProvider` in `src/sidebar/controls-view-provider.ts`
- [x] Remove Controls Editor HTML/JS from C2's webview bundle. C2 now renders Scope + Spectrum only.
- [x] Update C1 message routing: `controlsConfig` and `status` go to `controlsViewProvider`; Scope/Spectrum continue to C2.

### T22-2 — Convert Wiring Editor from `WebviewPanel` to `WebviewView` in C11 ✅

**Depends on:** T22-1 (C11 container and registration pattern established).

- [x] Implement `WiringViewProvider implements WebviewViewProvider` in `src/sidebar/wiring-view-provider.ts`
- [x] Remove `WiringPanel`/`createWebviewPanel()` from C1; `ds-ide: Open Wiring Editor` command now calls `executeCommand('ds-ide.wiringEditor.focus')`.
- [x] `retainContextWhenHidden: true` on both providers.

## Acceptance criteria (verify before close)

- **AC-34** — Controls Editor in secondary sidebar: open a ds-ide project; verify the Controls
  Editor appears as a persistent view in the right secondary sidebar without running a command.
  Hide the secondary sidebar and re-show it; verify Controls Editor still displays correct state.
  *(FR-CE-8)*
- **AC-35** — Wiring Editor in secondary sidebar: verify the Wiring Editor appears as a
  persistent view in the right secondary sidebar. Run `ds-ide: Open Wiring Editor`; verify the
  command reveals/focuses the view rather than opening a new floating panel. *(FR-WE-10)*

---

## Notes

- `retainContextWhenHidden: true` on both views prevents blank-state flicker on sidebar toggle,
  at the cost of keeping the webview alive in the background. Both views are lightweight (no
  audio I/O), so memory impact is negligible.
- The `emulatorState` message must be broadcast to both C2 and C11 controls view so grayed-out
  state on the Controls Editor is maintained when the sidebar is visible while the emulator state changes.
- No new IPC messages to the emulator runtime in this milestone.
