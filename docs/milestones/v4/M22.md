# M22 — Secondary Sidebar Panels

**Target version:** 0.4.3
**Status:** planned
**Closes:** AC-34, AC-35
**Decisions:** D21 (Controls Editor and Wiring Editor as secondary sidebar `WebviewView`s)
**Risks:** R23 (C2 split regression), R24 (`WebviewView` lifecycle)

---

## Goal

Move the Controls Editor and Wiring Editor from floating `WebviewPanel`s into persistent
`WebviewView`s in a ds-ide secondary sidebar container (C11). Both views are always accessible
in the right panel without running a command.

---

## Tasks

### T22-1 — Extract Controls Editor from C2 into C11 (`WebviewView`)

**Context:** C2 currently bundles Scope, Controls, and Spectrum in one webview panel. This
task extracts the Controls Editor section into a standalone `WebviewView` provider, leaving
C2 with Scope and Spectrum only.

- Add `contributes.viewsContainers.activitybar` entry for `ds-ide-sidebar` in `package.json`.
- Add two `contributes.views` entries under `ds-ide-sidebar`:
  - `ds-ide.controlsEditor` (name: "Controls")
  - `ds-ide.wiringEditor` (name: "Wiring")
- Implement `ControlsViewProvider implements WebviewViewProvider` in C1:
  - `resolveWebviewView()`: set HTML (Controls Editor slice, extracted from C2 bundle), wire
    `onDidReceiveMessage` with the same handlers currently in C2 for controls.
  - `onDidChangeVisibility()`: if `view.visible`, re-send `controlsConfig` and `emulatorState`
    to the view's webview.
  - Enable `retainContextWhenHidden: true` on the webview options.
- Remove Controls Editor HTML/JS from C2's webview bundle. C2 now renders Scope + Spectrum only.
- Update C1 message routing: `controlsConfig` and `emulatorState` (controls slice) go to
  `controlsViewProvider.view.webview`; Scope/Spectrum messages continue to the C2 panel.
- Regression test: AC-20, AC-21, AC-24, AC-25, AC-27, AC-28, AC-31 must remain green.

**DoD:**
- Controls Editor visible in right secondary sidebar without a command.
- Drag-handle rearrangement works (AC-24).
- Knob visual intact (AC-25).
- Scope, Spectrum unaffected (spot-check AC-20, AC-21).
- xruns counter still in header only (AC-31).
- Sidebar hide/show restores Controls Editor state correctly.

### T22-2 — Convert Wiring Editor from `WebviewPanel` to `WebviewView` in C11

**Depends on:** T22-1 (C11 container and registration pattern established).

- Implement `WiringViewProvider implements WebviewViewProvider` in C1:
  - `resolveWebviewView()`: set HTML (current C10 Wiring Editor), wire `onDidReceiveMessage`
    with the same handlers as current C10.
  - `onDidChangeVisibility()`: if `view.visible`, re-send `wiredPins` to the view.
  - Enable `retainContextWhenHidden: true`.
- Remove `vscode.window.createWebviewPanel()` call for the Wiring Editor from C1.
- Update `ds-ide: Open Wiring Editor` command: call
  `vscode.commands.executeCommand('ds-ide.wiringEditor.focus')` to reveal/focus the view
  instead of creating a new panel.
- Regression test: AC-19, AC-23, AC-29, AC-30, AC-35 must pass.

**DoD:**
- Wiring Editor visible in right secondary sidebar.
- `ds-ide: Open Wiring Editor` reveals and focuses the view (no new floating panel opens).
- Click-to-assign (AC-19) and Remove (AC-23) work correctly.
- ID labels legible (AC-29), USB port visible (AC-30).
- Sidebar hide/show restores Wiring Editor state.

## Notes

- `retainContextWhenHidden: true` on both views prevents blank-state flicker on sidebar toggle,
  at the cost of keeping the webview alive in the background. Both views are lightweight (no
  audio I/O), so memory impact is negligible.
- The `emulatorState` message must be broadcast to both C2 and C11 controls view so grayed-out
  state on the Controls Editor is maintained when the sidebar is visible while the emulator state changes.
- No new IPC messages to the emulator runtime in this milestone.
