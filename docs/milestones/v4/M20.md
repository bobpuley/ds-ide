# M20 — Controls Editor Single-Mode Handle UX (v0.4.1)

**Status:** planned
**Version:** 0.4.1
**Depends on:** M19
**Goal:** Replace the v3 two-mode Controls Editor (D18) with the single-mode handle-based UX (D19). Each control has a drag handle for rearrangement (always available) and a body for live interaction (available only while the emulator is running). Also upgrade pot controls to a hardware-style rotary knob visual.

---

## Context

The v3 Controls Editor shipped a Design / Run mode toggle (M17, D18). Post-v3 review identified this as the wrong UX: developers want to rearrange controls and interact with them in a single unified view, without switching modes. D19 replaces D18. The C9 parser, `controlsConfig` message contract, and IPC channels are unchanged — all changes are internal to C2.

AC-18 is retired (it tested the D18 two-mode panel). AC-24 and AC-25 are the v4 replacements.

## Tasks

### T20-1 — Implement drag-handle UX in Controls Editor C2

In the C2 Controls Editor webview:
- Remove the explicit Design / Run mode toggle from the panel header
- Add a **drag handle** to each rendered control (small grab icon; e.g. ⠿ glyph or equivalent)
- Dragging the handle rearranges the control on the canvas (existing positioning logic, now always active)
- When the emulator is stopped: control body is rendered but grayed-out; pointer events on the body are disabled
- When the emulator starts: control body becomes interactive (pot/button/LED); existing IPC channels unchanged
- Emulator running state is indicated in the panel header or a status area (replacing the mode label)
- Save rearrangement to `controllers.yaml` on save (unchanged from v3)

**DoD:**
- AC-24 passes: handle drag rearranges when emulator is stopped; body is non-interactive when stopped; body is interactive when running.
- No regression to AC-22 (yaml-only fallback).
- AC-18 is explicitly marked retired in the test suite (or test file is replaced).

---

### T20-2 — Pot visual: hardware-style rotary knob

In C2, replace the current pot slider with a rotary knob visual:
- Rendered as a circular knob resembling a real hardware pot
- Rotation angle encodes the current value
- Interaction model: **vertical drag** — click and drag up to increase value, drag down to decrease
- Look and feel consistent with the Wiring Editor panel aesthetic (same color palette, border radius, shadow)

**DoD:** AC-25 passes: pot renders as rotary knob; L&F matches Wiring Editor; interaction model works correctly.
