# M24 — Init Block Code Generation

**Target version:** 0.5.1
**Status:** released
**Closes:** AC-37
**Decisions:** D23 (Wiring Editor manages init block alongside declaration block)
**Assumptions:** A21 (ADC init grouping is representable as templated code)
**Risks:** R25 (ADC grouping complexity)

---

## Goal

When the developer wires a control in the Wiring Editor, ds-ide should write not just the
declaration (D16) but also the matching initialization call, so the effect compiles and runs
immediately without manual boilerplate.

---

## Tasks

### T24-1 — Extend C9 parser to parse `// ds-ide:controls:init:begin/end` block

- Add init block detection to C9 (pure function, same approach as declaration block):
  - Scan for `/^\/\/ ds-ide:controls:init:begin\s*$/`
  - Scan for `/^\/\/ ds-ide:controls:init:end\s*$/`
  - Return `{ initLines: string[], missingInitBlock: boolean }` alongside existing output.
- `missingInitBlock: true` is not an error — the block may not yet exist (will be created on
  first Wiring Editor write).
- Write unit tests for: block present, block absent, block with multiple init lines.

**DoD:**
- C9 returns correct `initLines` for a source with init block.
- C9 returns `missingInitBlock: true` for a source with only the declaration block.
- Unit tests pass.

### T24-2 — Extend controls-writer to manage init calls

> **Prerequisite:** Validate A21 before writing this task — run a `graphify query` on ADC
> init patterns to confirm the `adc.Init(cfgs[], n)` grouping assumption holds for all
> supported control types (pot/button/led). Adjust templates if the pattern differs.

- Extend the controls-writer module (C1) with init-block write support:

  **Init call templates per control type:**
  - pot (`AdcChannelConfig`): `  <varname>.InitSingle(daisy::seed::A<analogPin>);`
    Plus maintain the aggregate call at the END of the init block:
    `  hardware.adc.Init(<cfg1>, <cfg2>, ..., <n>);` — regenerated whenever pot count changes.
  - button (`Switch`): `  <varname>.Init(daisy::seed::D<pin>, hardware.AudioCallbackRate());`
  - led (`Led`): `  <varname>.Init(daisy::seed::D<pin>, false);`

- **Add device:** insert init line after last existing init line in block; regenerate
  `hardware.adc.Init()` line if a pot was added.
- **Remove device:** delete the device's init line; regenerate `hardware.adc.Init()` line
  if a pot was removed.
- **Create block if absent:** if `missingInitBlock: true`, insert the init block after
  `// ds-ide:controls:end` (or end of file, consistent with declaration block insertion rule).
- All writes via `vscode.WorkspaceEdit` (undoable). Validate markers at column 0 before writing
  (same safety rule as declaration block).

**DoD:**
- Adding a pot writes `varname.InitSingle(...)` and updates `hardware.adc.Init()`.
- Adding a button writes `varname.Init(...)`.
- Removing any device deletes its init line and (if pot) regenerates `adc.Init()`.
- Init block created if not present; existing block not duplicated.
- All writes undoable in VS Code.

### T24-3 — Wire Wiring Editor (C10/C11) to trigger init block writes

- Update the `wirePin` handler in C1 to call the init-block writer (T24-2) after the
  declaration writer (existing behavior).
- Update the `unwirePin` handler similarly.
- Re-parse with C9 (including new init block fields) and re-send updated state to C10/C11
  and C2 after each write.

**DoD:**
- Assigning a device in the Wiring Editor UI writes both declaration AND init line.
- Removing a device removes both declaration AND init line.
- AC-37 passes end-to-end.

## Acceptance criteria

- **AC-37** — Init block generation: open the Wiring Editor, assign a pot to an ADC pin and
  a button to a digital pin; verify: (a) `.cpp` contains both the declaration block (FR-WE-4)
  and a `// ds-ide:controls:init:begin/end` block with matching init calls; (b) removing the
  pot in the Wiring Editor deletes its init line from the init block. *(FR-CG-1)*

---

## Notes

- **A21 validation is a prerequisite for T24-2.** Run `graphify query "AdcChannelConfig init
  pattern adc.Init"` and inspect the Daisy examples before writing the ADC grouping logic.
- The `hardware.adc.Init()` aggregate line must list configs in the order they were assigned
  (insertion order). Do not sort by pin number — channel index must match the order in the
  declaration block to avoid mis-mapping controls to ADC channels.
- The init block does not affect `controllers.yaml` or the Controls Editor — those remain
  driven by the declaration block only.
- M24 depends on M22 being shipped: T24-3 targets the C11 Wiring Editor WebviewView; writing
  against a deprecated C10 `WebviewPanel` would require rebasing.
